# 数据正本与 Agent 协作

> 从 v0.2.19 起，LabFlow 的「真相」是磁盘上的纯文本文件，不是数据库。
> 数据库退化成缓存；文件在哪儿、长什么样、谁能改，都写在下面。

---

## 一、文件在哪

数据根默认 `D:\学习\labflow`（可在应用里改）：

```
D:\学习\labflow\
├─ 仓库.yml              试剂仓库正本（所有试剂、分组、余量）
├─ 工程\
│   ├─ 261118.yml        每个实验工程一个文件
│   └─ ...
├─ 导出\                 导出的 SOP / 截图（默认不放数据副本）
└─ .agent-lock           Agent 锁（只在 Agent 操作期间存在）
```

一个仓库文件 + 每个工程一个文件，改动一个工程只动它自己那份。

## 二、读写规矩

| 时机 | 做什么 |
|---|---|
| 启动 | **只读**。文件存在就只载入，一个字节都不写；文件不存在才由数据库生成一次 |
| 保存 | 只写工程正本（不扣试剂、不动仓库） |
| 结束实验 | 才扣试剂、把中间产物入仓，**两个正本文件都写成功之后**才改数据库 |
| 外部改动 | 应用自检测到文件被改，界面自动重载；有未保存改动时只提示、不覆盖 |

几条保护：

- 写盘带「写前指纹」：期间文件被别人改过，就**不写**，改为重读并提示「仓库文件已被外部修改，已重新载入」。
- 文件解析失败（比如 YAML 重复键）当**坏文件**处理：另存 `仓库.broken-<时间戳>.yml`，本次只读、不回写，界面提示。
- 试剂条数骤降只有在「显式删除」时才允许落盘，防止一次 bug 把仓库抹掉。
- 工程已是 `completed` 时不允许再次结算，避免二次扣减。
- 同名但不同 id 的工程不会被写成同一个文件（后者自动改名为 `名字-2.yml`）。

## 三、文件格式

```yaml
schemaVersion: 2
project:
  id: 92b94643-…        # 工程的身份证，改名也能认回来
  name: 261118
  date: '2026-11-23'
  status: draft          # draft | completed
tubes:
  - id: …
    name: Tri-a
    type: source         # source | intermediate | sample | waste | buffer
    totalVolume: 20 μL
    remainingVolume: 20 μL
    substances:
      - name: Tri-a
        concentration: 100 μM
    x: -45               # 画布坐标（导出时的排布）
    boardY: 60
connections:
  - id: …
    from: <tube id>
    to: <tube id>
    volume: 5 μL
reagents: […]            # 工程里用到的试剂引用
```

- 数值一律写成 `<数值> <单位>`，读入时统一归一到 `µM / µL` 再算，写回按该管自己的单位。
- 显示时自动选好读的档：`1000000 µM` 显示成 `1 M`，`2985 µL` 显示成 `2.99 mL`。
- 别手改 `id`；改浓度、体积、名字都安全。

## 四、Agent 锁

Agent 要批量改文件时，先落一个锁文件 `D:\学习\labflow\.agent-lock`：

```json
{"pid":4132,"agent":"codex/墨林","project":"AD-5.2","note":"改 12 个样品浓度","startedAt":"2026-11-22T15:56:39.053Z"}
```

- 界面检测到「锁的正是当前工程」→ 冻住：画布不能拖、保存/新建/结束实验按钮全灰，顶部黄条写明谁在改什么、改了多久。
- 超过 15 分钟：黄条变红，提示「可能忘记解锁了」。
- 锁的是别的工程：只提示，不冻结。
- 强制解锁要二次确认（「Agent 可能仍在写文件…」）。
- 锁里现在多一个 `owner` 字段（`agent` ＋ 加锁时刻派生的 token）。**同一个 owner 跨进程能自己解锁**，别人的锁必须 `--force` 才能删。
- 旧锁没有 `owner` 字段：读到时按「需要 `--force`」处理（兼容策略）。

命令行工具（免开界面）：

```bash
node scripts/agent-lock.cjs lock --project 261118 --note "改 12 个样品浓度"
node scripts/agent-lock.cjs status
node scripts/agent-lock.cjs unlock            # 同 owner 直接解开
node scripts/agent-lock.cjs unlock --force    # 别人的锁
```

`labflow` 命令行同样：`labflow lock <工程> --note "..."`、`labflow unlock <工程> [--force]`；
`--owner` 或环境变量 `LABFLOW_LOCK_OWNER` 可显式指定身份，不传就用默认 `cli`。

## 五、命令行 `labflow`

`npm run build:cli` 生成 `dist-cli/labflow.mjs`；包安装后可 `labflow <命令>`。
所有命令支持 `--json`，默认**只算不写**，退出码 `0` 成功 / `1` 有问题 / `2` 用法错。

| 命令 | 作用 | 会写文件吗 |
|---|---|---|
| `list` | 列出所有工程与数据根 | 否 |
| `validate <工程>` | 跑界面「检查」那套规则，报错逐条带试管名 | 否 |
| `calc <工程>` | 每管最终成分与体积 | 否 |
| `diff <工程A> <工程B>` | 两个工程差在哪几管、多少体积 | 否 |
| `export <工程> --out <目录>` | 只写 SOP（`.md`） | 是 |
| `lock` / `unlock` | 加锁 / 解锁 | 只动锁文件 |
| `complete <工程> [--apply]` | 结算：扣试剂、中间产物入仓 | 加 `--apply` 才写 |

`--root <目录>` 或环境变量 `LABFLOW_DATA_ROOT` 可指定别处的数据根（拿副本来试跑）。

## 六、哪些必须在界面里做

- **流程图 PNG**：是截当前画布，必须先把那个工程打开。
- **白板 `.canvas`**：同样需要工程在界面上。
- **导出的默认值**（目录、文件名模板、放不放开子文件夹、缩放比例 1.6×、导哪几样）在「讲述者 → 3. 导出工程」里调。
- **删除工程**：界面删除会把文件归档到 `工程\_deleted\<时间戳>-<原名>.yml`（不再留在 `工程\` 里冒充工程），需要恢复就从那里挪回来。

## 七、导出默认值

| 项 | 默认 |
|---|---|
| SOP `.md` | 开 |
| 截图 `.png` | 开 |
| 白板 `.canvas` | 关 |
| 数据 `.yml` 副本 | 关（勾了也只当备份，永不回读） |
| 保存时自动导出 | 开 |
| 画布缩放 | 横向 1.6× / 纵向 1.6× |

## 八、结算与回退的边界

- **只有「结束实验」扣试剂**，保存只写工程文件，不动仓库。
- 结束实验会一次做成四件事：扣原料余量、把中间产物入仓、写 `status: completed` + `completedAt`、记试管历史。
- 结果不确定时先看 `仓库.yml` 是否已经变；写盘顺序是「先仓库、后工程」，中途失败会回滚文件并在提示里说明真实状态——**不会再出现「都说没改、其实文件已变」**。
- 已结束的工程不能重复结算（CLI 也拒），要重算得先回退成草稿。
- 回退（历史页）只把**本工程结算时用掉的量**反向加回，基底是当前 `仓库.yml`；期间别的新增试剂不受影响。本工程新入仓的中间产物会被移除（余量已被别人动过的会跳过并说明）。
- 回退只允许对 `status: completed` 的工程做。

## 九、从笔记里点链接打开工程

SOP 头部和讲述者页的「复制工程链接」给的是：

```
labflow://open?project=<工程名>[&id=<工程 id>]
```

- 应用没开时点它：冷启动也直接落在「实验模拟」并载入该工程（主进程只入槽，渲染层就绪后主动来取，不靠一次性推送）。
- 应用已开时点它：前置窗口 + 热切换到该工程。
- 已结束的工程照样能打开，只是只读并带黄条。
- 只给名字、找不到工程时不猜，直接提示「找不到」。

## 十一、Agent 改完工程文件之后必须做的事（操作规程）

> **2026-11-23 更正**：本文早先写「LabFlow 不监听文件」，那是热加载上线前的状态。现在主进程有
> `electron/storeWatcher.ts` + `electron/main.ts:1808` `watchDir`（`fs.watch` 根目录与 `工程/`，150 ms 去抖），
> 渲染端 `src/renderer/src/utils/storeHotReload.ts:90` `useStoreHotReload` 收广播后按 `planHotReload`（`:46`）处理，
> **界面会自动重载**。所谓「重新载入」按钮只在实验页那条黄条里，不是常驻顶栏按钮。

1. **不必要求用户去点「重新载入」。** 正常情况改完盘界面自己就变了（并弹 toast「仓库文件已更新，已重新载入」/「工程文件已更新，已重新载入」）。唯一会被拦下的情形：改的是**当前正开着的工程**、且界面有未保存改动（dirty）——此时不覆盖，只在实验页顶部挂一条「⚠️ 工程文件已被外部修改：<文件名>」，附「重新载入」「先不管」（`ExperimentPage.tsx:1516-1527`）。
2. **不要替用户点「保存」。** 「保存」写的是界面内存里的内容；内存可能还是旧的，一点就把旧内容写回磁盘、盖掉 Agent 刚写的文件。要落界面改动，等用户确认后再点。
3. **弹「重新载入 / 覆盖」时选「重新载入」。** 保存前会比对 stat（`ExperimentPage.tsx:1146-1160`、`src/core/store/fileStat.ts`），文件被外部改过就弹框：选「重新载入」= 保留磁盘版本（也就是 Agent 写的版本）；选「覆盖」= 丢掉磁盘改动、把界面旧内容写回去。
4. **单位写希腊字母 `μ`（U+03BC）**，不是微符号 `µ`（U+00B5）。应用自己重存会写成后者，属待修缺陷；Agent 回写文件前后都检查一遍，别把错的单位当「规范」抄下去。
5. **标准动作顺序**：
   1. 写/改 `D:\学习\labflow\工程\<名>.yml`
   2. `node dist-cli/labflow.mjs validate <名>` —— 退出码必须是 `0`
   3. `node dist-cli/labflow.mjs calc <名>` —— 核对关键浓度与用量
   4. 回复里提醒用户重载
   5. 用户重载后，一起看效果
6. **三个已知未修缺陷**——**不影响 `validate`/`calc` 与界面读写**，知道就行，别当新 bug 报；排期在第十节：
   - **导出的流程图 PNG 会裁边**：`captureBoardPng`（`src/renderer/src/utils/boardCapture.ts`）在画布很密时（例如 55 支管）只截到可视区；根因是 `fitView` 没显式给 `minZoom`，React Flow 默认下限 0.5 把缩放夹住了。
   - **`validate --json` 的 `concentration_mismatch` 没有 `message`**：见第十节第 9 条（旧构建产物，重建即可）。
   - **应用重存把 `μ` 写成 `µ`、并去掉 `name:` 的引号**：见第十节第 10 条。
